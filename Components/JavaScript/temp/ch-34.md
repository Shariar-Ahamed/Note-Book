# 34.1 Package কী?

**Package** হলো reusable code-এর একটি collection, যেটা অন্য developer নিজের project-এ ব্যবহার করতে পারে।

ধরো তুমি নিজে একটা function লিখলে:

```javascript
function add(a, b) {
    return a + b;
}
```

কিন্তু একজন developer এমন একটি library তৈরি করল যেখানে হাজার হাজার useful function আছে।

তুমি সেই library install করে ব্যবহার করতে পারো।

```text
Your Project
     │
     ├── Your Code
     │
     └── External Packages
            │
            ├── React
            ├── Express
            ├── Axios
            ├── Lodash
            └── etc.
```

# 34.2 NPM কী?

* package update
* dependency manage
* scripts run

### Example

```bash

```

এখানে:

```text
npm

lodash
```

# 34.5 `package.json` কী?

`package.json` হলো JavaScript/Node project-এর **project configuration এবং dependency manifest file**।

Example:

```json
{
  "name": "my-project",
  "version": "1.0.0",
  "description": "My JavaScript project",
  "main": "index.js",
  "scripts": {
    "start": "node index.js"
  },
  "dependencies": {},
  "devDependencies": {}
}
```

এটি project-এর গুরুত্বপূর্ণ information ধরে রাখে।

---

# 34.6 `package.json`-এর গুরুত্বপূর্ণ fields

| Field             | কাজ                          |
| ----------------- | ---------------------------- |
| `name`            | Project/package name         |
| `version`         | Project version              |
| `description`     | Project description          |
| `main`            | Entry point                  |
| `scripts`         | Commands                     |
| `dependencies`    | Production dependencies      |
| `devDependencies` | Development dependencies     |
| `type`            | Module system                |
| `engines`         | Runtime version requirements |

# 34.9 Semantic Versioning — SemVer

সাধারণ format:

```text
MAJOR.MINOR.PATCH
```

Example:

```text
2.5.3
```

মানে:

```text
2 → Major
5 → Minor
3 → Patch
```

---

## Major

Breaking changes:

```text
1.0.0
↓
2.0.0
```

আগের code compatibility নষ্ট হতে পারে।

---

## Minor

নতুন backward-compatible feature:

```text
1.2.0
↓
1.3.0
```

---

## Patch

Bug fix:

```text
1.2.3
↓
1.2.4
```

# 34.14 `package-lock.json`

এটি dependency tree-এর **exact resolved versions** এবং related metadata lock করে রাখে।

Example:

```text
package.json
      ↓
Version range
      ↓
package-lock.json
      ↓
Exact dependency resolution
```

এটি team এবং CI/CD environment-এ consistent installation-এর জন্য গুরুত্বপূর্ণ।

---

# 34.15 `package.json` vs `package-lock.json`

| `package.json`                 | `package-lock.json`                     |
| ------------------------------ | --------------------------------------- |
| Project/dependency declaration | Resolved dependency tree lock           |
| Version range থাকতে পারে       | Exact resolved versions record করে      |
| Human-edited                   | সাধারণত npm manage করে                  |
| Project configuration          | Reproducible installation-এ সাহায্য করে |

### GitHub-এ কোনটা রাখব?

```text
package.json       ✅
package-lock.json  ✅
node_modules       ❌
```

# 34.17 Dependency vs DevDependency

এটি খুব important।

```bash

```

```json
  "dependencies": {
```

---

## DevDependency

Development-এর সময় দরকার:

```bash

```

অথবা:


```json
  }
}
```

# 34.38 Tree Shaking

Unused code বাদ দেওয়ার optimization-কে tree shaking বলা হয়।

ধরো:

```javascript
export function add() {}

export function subtract() {}

export function multiply() {}
```

তুমি শুধু:

```javascript
import { add } from "./math.js";
```

ব্যবহার করলে build tool বুঝতে পারে অন্য exports ব্যবহৃত হচ্ছে না এবং production output-এ সেগুলো বাদ দেওয়ার সুযোগ পেতে পারে।

⚠️ Tree shaking সবসময় perfect হয় না; static analyzability এবং package/module structure গুরুত্বপূর্ণ।

# 34.39 Minification

Code-এর unnecessary whitespace/comments ইত্যাদি কমিয়ে output ছোট করা হয়।

Before:

```javascript
function add(a, b) {
    return a + b;
}
```

Production output conceptually এমন হতে পারে:

```javascript
function add(a,b){return a+b}
```

এতে download size কমতে পারে।

# ⚠️ খুব গুরুত্বপূর্ণ Security Rule

```text
❌ Database password
❌ Private credentials
❌ Server secret
```

Frontend-এ কখনো real secret রাখবে না।

# 34.51 Version Ranges

`package.json`-এ:

```json
{
  "dependencies": {
    "example": "^1.2.3"
  }
}
```

এখানে `^` version range বোঝায়।

আর:

```json
"example": "~1.2.3"
```

এর behavior আলাদা।

---

# 34.52 `^` এবং `~`

সাধারণ SemVer context-এ:

### Caret

```text
^1.2.3
```

সাধারণত compatible minor/patch updates allow করে, কিন্তু `2.0.0` নয়।

### Tilde

```text
~1.2.3
```

সাধারণত patch-level updates-এর মধ্যে থাকে।

⚠️ Exact behavior package versioning rules এবং major version (`0.x`) অনুযায়ী nuance থাকতে পারে।

---

# 34.53 Exact Version

```json
{
  "dependencies": {
    "example": "1.2.3"
  }
}
```

এতে range না রেখে exact version declare করা হয়।

কিন্তু reproducible installation-এর জন্য lockfile-ও গুরুত্বপূর্ণ।

# 34.65 Common Mistakes

### ❌ `node_modules` GitHub-এ push করা

```gitignore
node_modules/
```

### ❌ `.env` public repository-তে push করা

```gitignore
.env
```

### ❌ package blindly update করা

Update-এর আগে breaking changes/changelog/documentation দেখা উচিত।

### ❌ `npm audit fix --force` blindly চালানো

এতে breaking upgrade হতে পারে।

### ❌ সব package global install করা

Project dependency local রাখা সাধারণত ভালো।

### ❌ package-lock delete করে দেওয়া

কারণ reproducible dependency installation-এর সুবিধা নষ্ট হতে পারে।

### ❌ Unknown package blindly install করা

আগে package:

* downloads
* repository
* maintainer
* documentation
* recent activity
* vulnerabilities

দেখা ভালো।
