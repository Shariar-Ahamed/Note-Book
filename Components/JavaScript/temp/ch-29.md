# 📘 Chapter 29 — JavaScript Execution Model & Event Loop

JavaScript-এর **Execution Model + Event Loop** বুঝতে পারলে `Promise`, `async/await`, `fetch()`, `setTimeout()`, DOM events—এগুলো **কেন কোন order-এ execute হয়** সেটা পরিষ্কার হয়ে যাবে।

এটা JavaScript-এর সবচেয়ে গুরুত্বপূর্ণ advanced concepts-এর একটি। বিশেষ করে **Frontend interview** এবং **React/Node.js development**-এর জন্য খুব গুরুত্বপূর্ণ।

---

# 29.1 JavaScript Execution Model কী?

JavaScript code কীভাবে:

1. Read করে
2. Execute করে
3. Function call handle করে
4. Asynchronous কাজ manage করে
5. পরে result execute করে

—এই পুরো system-টাই JavaScript-এর **Execution Model**।

সহজভাবে:

```text
JavaScript Code
      ↓
Execution Context
      ↓
Call Stack
      ↓
Synchronous Execution
      ↓
Async কাজ → Host APIs
      ↓
Task / Microtask Queue
      ↓
Event Loop
      ↓
Call Stack
      ↓
Execution
```

---

# 29.2 JavaScript কি Single-Threaded?

সাধারণ JavaScript execution model-এ একটি main JavaScript execution thread-এ এক সময়ে **একটি piece of JavaScript code** execute হয়।

তাই আমরা বলি:

> JavaScript is single-threaded.

উদাহরণ:

```javascript
console.log("A");
console.log("B");
console.log("C");
```

Output:

```text
A
B
C
```

একসাথে:

```text
A
B
C
```

execute হয় না।

একটির execution শেষ হওয়ার পর পরেরটি execute হয়।

### কিন্তু একটা গুরুত্বপূর্ণ বিষয়

এর মানে এই নয় যে browser একেবারেই parallel কাজ করতে পারে না।

Browser/Node.js-এর মতো **host environment** JavaScript-এর বাইরে বিভিন্ন কাজ handle করতে পারে—যেমন:

* Timer
* Network request
* File I/O
* DOM events
* Background operations

এবং JavaScript পরে সেই কাজের result handle করে।

# 29.5 Call Stack কী?

**Call Stack** হলো JavaScript-এর function execution track করার একটি mechanism।

সহজভাবে:

> কোন function এখন execute হচ্ছে এবং কোন function থেকে call হয়েছে—Call Stack সেটা track করে।

উদাহরণ:

```javascript
function one() {
    two();
}

function two() {
    three();
}

function three() {
    console.log("Hello");
}

one();
```

Execution:

```text
one()
  ↓
two()
  ↓
three()
```

Call Stack:

```text
┌─────────┐
│ three() │
├─────────┤
│ two()   │
├─────────┤
│ one()   │
└─────────┘
```

`three()` শেষ হলে:

```text
three() removed
```

তারপর:

```text
two() removed
```

তারপর:

```text
one() removed
```

# 29.10 Heap কী?

**Heap** হলো memory-এর একটি area যেখানে JavaScript runtime dynamically allocated data রাখে।

যেমন:

```javascript
const user = {
    name: "Ripon",
    age: 23
```

Array:

```javascript
const numbers = [10, 20, 30];
```

Function/object-এর মতো reference-based data heap-এর সাথে সম্পর্কিত।

সহজভাবে:

```text
Call Stack
→ execution tracking

Heap
→ dynamically allocated objects/data
```

Memory Management বিস্তারিতভাবে আমরা **Chapter 30**-এ দেখব।

# 29.11 Execution Context কী?

JavaScript যখন code execute করে, তখন তার জন্য একটি **Execution Context** তৈরি হয়।

সহজভাবে:

> JavaScript code execute করার জন্য যে environment তৈরি হয় সেটাই Execution Context।

প্রধানত:

### 1. Global Execution Context

সবচেয়ে প্রথমে তৈরি হয়।

### 2. Function Execution Context

প্রতিবার function call হলে তৈরি হয়।

### 3. Eval Execution Context

`eval()` ব্যবহার করলে তৈরি হতে পারে। Modern development-এ সাধারণত avoid করা হয়।

---

# 29.12 Global Execution Context

এই code:

```javascript
const name = "Ripon";

console.log(name);
```

execute করার সময় JavaScript একটি:

```text
Global Execution Context
```

তৈরি করে।

এখানে global-level variables/functions এবং অন্যান্য execution information থাকে।

---

# 29.13 Function Execution Context

এই code:

```javascript
function greet(name) {
    console.log(name);
}

greet("Ripon");
```

`greet()` call হলে নতুন Function Execution Context তৈরি হয়।

```text
Global Execution Context
        ↓
Function Execution Context
        ↓
greet()
```

`greet()` শেষ হলে function context চলে যায়।

---

# 29.14 Execution Context-এর Creation Phase

একটি execution context তৈরি হওয়ার সময় JavaScript আগে execution-এর জন্য environment প্রস্তুত করে।

সহজভাবে:

```text
Creation Phase
      ↓
Environment তৈরি
      ↓
Declarations setup
      ↓
Execution Phase
      ↓
Code execute
```

এই কারণে আমরা **hoisting** দেখতে পাই।

উদাহরণ:

```javascript
console.log(x);

var x = 10;
```

Output:

```text
undefined
```

কারণ `var x` declaration আগে থেকেই environment-এ setup হয়।

তবে:

```javascript
console.log(x);

let x = 10;
```

এতে error:

```text
ReferenceError
```

কারণ `let` এবং `const` declaration execution-এর আগে scope-এ থাকলেও initialization-এর আগে access করা যায় না। এই সময়টাকে **Temporal Dead Zone (TDZ)** বলা হয়।

# 29.16 Lexical Environment

JavaScript variables কোথায় থাকবে এবং কোন variable কোথা থেকে accessible হবে—এটার সাথে **Lexical Environment** সম্পর্কিত।

উদাহরণ:

```javascript
const globalName = "Ripon";

function greet() {
    const message = "Hello";

    console.log(globalName);
    console.log(message);
}

greet();
```

`greet()` access করতে পারে:

```text
message
globalName
```

কারণ scope chain-এর মাধ্যমে outer environment পাওয়া যায়।

---

# 29.17 Scope Chain

```javascript
const a = 10;

function outer() {
    const b = 20;

    function inner() {
        const c = 30;

        console.log(a);
        console.log(b);
        console.log(c);
    }

    inner();
}

outer();
```

`inner()` দেখতে পারে:

```text
c → নিজের scope
b → outer scope
a → global scope
```

এটাই scope chain-এর basic ধারণা।

Closure-এর সাথে এই বিষয়টি খুব গুরুত্বপূর্ণ—যেটা Chapter 26-এ আমরা বিস্তারিত করেছি।

# 29.21 Event Loop কী?

Event Loop হলো এমন একটি mechanism যা দেখে:

> Call Stack কখন empty হয়েছে এবং queued asynchronous callbacks কখন JavaScript-এর execution-এর জন্য Stack-এ পাঠানো যাবে।

Simplified model:

```text
          ┌───────────────┐
          │  Call Stack   │
          └───────┬───────┘
                  │
             Stack Empty?
                  │
                  ▼
          ┌───────────────┐
          │  Event Loop   │
          └───────┬───────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
 Microtask Queue        Task Queue
```

# 29.22 Task Queue / Macrotask Queue

Task queue-তে বিভিন্ন asynchronous callback অপেক্ষা করতে পারে।

উদাহরণ:

```javascript
setTimeout(() => {
    console.log("Timer");
}, 0);
```

Timer-এর callback ready হলে task queue-তে যেতে পারে।

আরও উদাহরণ:

* `setTimeout`
* `setInterval`
* কিছু DOM events
* অন্যান্য host-scheduled tasks

---

# 29.23 Microtask Queue

Microtask Queue সাধারণত asynchronous callbacks-এর জন্য ব্যবহৃত হয় যেগুলো current task শেষ হওয়ার পর দ্রুত execute হওয়ার জন্য schedule হয়।

সবচেয়ে গুরুত্বপূর্ণ:

```javascript
Promise.then()
Promise.catch()
Promise.finally()
queueMicrotask()
```

Browser-এ `MutationObserver`-ও microtask mechanism ব্যবহার করে।

# 29.24 সবচেয়ে গুরুত্বপূর্ণ Rule 🔥

Simplified browser model:

```text
Current JavaScript Task
        ↓
Call Stack Empty
        ↓
Microtasks Drain
        ↓
Browser may render
        ↓
Next Task
```

অর্থাৎ:

> **Microtask সাধারণত next task-এর আগে execute হয়।**

এটা Event Loop-এর সবচেয়ে গুরুত্বপূর্ণ concept।

# 29.30 Nested Microtasks


# 29.46 Microtask Starvation

যদি আমরা continuously microtask তৈরি করতে থাকি:

```javascript
    queueMicrotask(loop);
```

ফলে:

```text
Microtasks
Microtasks
Microtasks
Microtasks
...
```

এবং অন্য tasks/rendering অনেক delay হতে পারে।

এটাকে broadly:

> **Microtask Starvation**

বলা হয়।
