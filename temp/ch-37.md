# 37.9 — Module Pattern

Module Pattern-এর মূল উদ্দেশ্য:

> Related code এক জায়গায় রাখা এবং প্রয়োজনীয় অংশই বাইরে expose করা।

আগে JavaScript-এ:

```javascript
const userModule = (() => {

    let users = [];

    function addUser(user) {
        users.push(user);
    }

    function getUsers() {
        return users;
    }

    return {
        addUser,
        getUsers
    };

})();
```

এখানে:

```text
users
```

private।

কিন্তু:

```text
addUser()
getUsers()
```

public।

# 37.12 — Singleton Pattern

Singleton-এর উদ্দেশ্য:

> একটি class/object-এর একটিমাত্র shared instance রাখা।

Real-life:

```text

     ↓
Configuration
     ↓
One shared instance
```

---

## Simple Example

```javascript
class Database {

    static instance;

    constructor() {

        if (Database.instance) {
            return Database.instance;
        }

        Database.instance = this;
    }

}
```

Use:

```javascript
const db1 = new Database();
const db2 = new Database();

console.log(db1 === db2);
```

Output:

```text
true
```

# 37.14 — Factory Pattern

Factory Pattern object creation-এর logic আলাদা করে।

ধরো:

```javascript

    if (type === "admin") {

            role: "admin",

    if (type === "user") {
        return {

```

Use:

```javascript

```

# 37.16 — Builder Pattern

যখন object অনেক configuration/optional property নিয়ে তৈরি হয়, তখন Builder useful।

ধরো:

```javascript
const user = {
    name: "Ripon",
    age: 25,
    email: "ripon@example.com",
    role: "admin",
    active: true
};
```

অনেক field থাকলে Builder:

```javascript
class UserBuilder {

    constructor() {
        this.user = {};
    }

    setName(name) {
        this.user.name = name;
        return this;
    }

    setEmail(email) {
        this.user.email = email;
        return this;
    }

    setRole(role) {
        this.user.role = role;
        return this;
    }

    build() {
        return this.user;
    }
}
```

Use:

```javascript
const user = new UserBuilder()
    .setName("Ripon")
    .setEmail("ripon@example.com")
    .setRole("admin")
    .build();
```

# 37.19 — Adapter Pattern

Adapter incompatible interface-কে compatible interface-এ convert করে।

Real-life:

```text
USB-C Laptop
      ↓
Adapter
      ↓
HDMI Monitor
```

Software-এও একই ধারণা।

ধরো:

```javascript
class OldPaymentSystem {

    makePayment(amount) {
        return `Paid ${amount}`;
    }

}
```

কিন্তু নতুন system চায়:

```javascript
pay(amount)
```

Adapter:

```javascript
class PaymentAdapter {

    constructor(oldSystem) {
        this.oldSystem = oldSystem;
    }

    pay(amount) {
        return this.oldSystem.makePayment(amount);
    }

}
```

Use:

```javascript
const oldSystem = new OldPaymentSystem();

const payment = new PaymentAdapter(oldSystem);

console.log(payment.pay(1000));
```

# 37.23 — Higher-Order Function as Decorator

Original:

```javascript
}
```


Output:

```text

```

Return:

```text

```

# 37.28 — Observer Pattern

Observer Pattern-এর মূল idea:

> একটি object-এর state পরিবর্তন হলে interested observers-কে notify করা।

Real-life:

```text

      ↓
New Video
      ↓
Subscribers
      ↓
Notification
```

---

# 37.29 — Observer Example

```javascript
class Subject {

    constructor() {
        this.observers = [];
    }

    subscribe(observer) {
        this.observers.push(observer);
    }

    notify(data) {

        this.observers.forEach(observer => {
            observer(data);
        });

    }

}
```

Use:

```javascript
const news = new Subject();

news.subscribe(data => {
    console.log("User 1:", data);
});

news.subscribe(data => {
    console.log("User 2:", data);
});

news.notify("New article published");
```

Output:

```text
User 1: New article published
User 2: New article published
```

# 37.31 — Pub/Sub Pattern

Observer-এর সাথে related হলেও Pub/Sub-এ publisher এবং subscriber সরাসরি একে অপরকে জানে না।

```text
Publisher
    ↓
 Event Bus
    ↓
Subscriber
```

---

# 37.32 — Simple Pub/Sub

```javascript
class EventBus {

    constructor() {
        this.events = {};
    }

    subscribe(event, callback) {

        if (!this.events[event]) {
            this.events[event] = [];
        }

        this.events[event].push(callback);
    }

    publish(event, data) {

        const callbacks = this.events[event] || [];

        callbacks.forEach(callback => {
            callback(data);
        });

    }
}
```

Use:

```javascript
const bus = new EventBus();

bus.subscribe("login", user => {
    console.log("Welcome", user.name);
});

bus.publish("login", {
    name: "Ripon"
});
```

Output:

```text
Welcome Ripon
```

---

# 37.33 — Observer vs Pub/Sub

| Observer                | Pub/Sub                                    |
| ----------------------- | ------------------------------------------ |
| Subject knows observers | Publisher usually doesn't know subscribers |
| Direct relationship     | Event channel/message bus                  |
| Simpler                 | More decoupled                             |
| State changes useful    | Event communication useful                 |

# 37.34 — Strategy Pattern

Strategy Pattern:

> একই কাজ করার multiple algorithm/strategy থাকলে runtime-এ প্রয়োজন অনুযায়ী strategy নির্বাচন করা।

ধরো payment:

```text
Card
PayPal
Bank
Crypto
```

একটি interface/contract-এর মাধ্যমে:

```javascript
class PaymentProcessor {

    constructor(strategy) {
        this.strategy = strategy;
    }

    pay(amount) {
        return this.strategy.pay(amount);
    }

}
```

Strategies:

```javascript
const cardPayment = {
    pay(amount) {
        return `Card payment: ${amount}`;
    }
};

const bankPayment = {
    pay(amount) {
        return `Bank payment: ${amount}`;
    }
};
```

Use:

```javascript
const processor =
    new PaymentProcessor(cardPayment);

console.log(processor.pay(1000));
```

# 37.36 — Command Pattern

Command Pattern:

> কোনো operation-কে object হিসেবে represent করা।

ধরো text editor:


Command:

```javascript
        this.text = text;
    }

    execute() {
        this.editor.add(this.text);
    }

    undo() {
        this.editor.remove(this.text);
    }

}
```

এখানে action-টি object হয়ে গেল।

# 37.42 — Dependency Injection

Dependency Injection বা **DI** হলো:

> কোনো object-এর প্রয়োজনীয় dependency নিজে তৈরি না করে বাইরে থেকে provide করা।

খারাপ coupling:

```javascript
class UserService {

    constructor() {
        this.database = new MySQLDatabase();
    }

}
```

এখানে UserService নিজেই database তৈরি করছে।

---

# 37.43 — Dependency Injection Example

Better:

```javascript
class UserService {

    constructor(database) {
        this.database = database;
    }

}
```

তারপর:

```javascript
const database = new MySQLDatabase();

const userService =
    new UserService(database);
```

```text
    ↓
```

```text
    ↓
Repository
    ↓
Database
```

Repository:

```javascript
class UserRepository {

    async findById(id) {
        return db.users.findById(id);
    }

}
```

Service:

```javascript
class UserService {

    constructor(userRepository) {
        this.userRepository = userRepository;
    }

    async getUser(id) {
        return this.userRepository.findById(id);
    }

}
```

এতে database implementation change করা সহজ হয়।

# 37.51 — Separation of Concerns

# 37.52 — DRY

**DRY = Don't Repeat Yourself**

খারাপ:

```javascript
function adminLogin() {
    // same validation
}

function userLogin() {
    // same validation
}
```

Better:

```javascript
function validateLogin(data) {
    // shared validation
}
```

তারপর:

```javascript
validateLogin(adminData);
validateLogin(userData);
```

# 37.53 — KISS

**KISS = Keep It Simple**

অতিরিক্ত complex architecture সবসময় ভালো নয়।

যদি problem:

```javascript
function add(a, b) {
    return a + b;
}
```

হয়, তাহলে ৫টি design pattern দরকার নেই। 😄

Pattern complexity তৈরি করার জন্য নয়।

# 37.54 — YAGNI

যে feature এখন দরকার নেই, শুধু ভবিষ্যতে লাগতে পারে ভেবে architecture over-engineer করো না।

```text
Need today
   ↓
Build today
```

# 37.66 — Mini Real-World Example

ধরো তুমি একটি **E-commerce Order System** বানাচ্ছো।

Architecture:

```text
User
 ↓
OrderController
 ↓
OrderService
 ↓
PaymentStrategy
 ↓
PaymentGateway
 ↓
Repository
 ↓
Database
```

### Payment Strategy

```javascript
const card = {
    pay(amount) {
        return `Card: ${amount}`;
    }
};

const bank = {
    pay(amount) {
        return `Bank: ${amount}`;
    }
};
```

### Service

```javascript
class OrderService {

    constructor(paymentStrategy) {
        this.paymentStrategy = paymentStrategy;
    }

    checkout(amount) {
        return this.paymentStrategy.pay(amount);
    }

}
```

Use:

```javascript
const service =
    new OrderService(card);

console.log(service.checkout(2000));
```

Output:

```text
Card: 2000
```

Payment method change:

```javascript
const service =
    new OrderService(bank);
```

মূল `OrderService` code পরিবর্তন করতে হয়নি।

এটাই Strategy + Dependency Injection-এর practical combination।
