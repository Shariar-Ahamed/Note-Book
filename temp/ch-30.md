# 📘 Chapter 30 — JavaScript Memory Management & Garbage Collection

JavaScript-এর **Memory Management** বুঝলে তুমি বুঝতে পারবে:

* Variable কোথায় থাকে?
* Object/Array memory-তে কীভাবে রাখা হয়?
* Reference কী?
* Garbage Collection কীভাবে কাজ করে?
* Memory Leak কী?
* Closure কি memory ধরে রাখে?
* DOM element memory-তে আটকে থাকতে পারে কীভাবে?
* `WeakMap` / `WeakSet` কেন দরকার?
* বড় application-এ memory কেন বাড়তে থাকে?

বিশেষ করে **Frontend, React, Node.js এবং performance optimization**-এর জন্য এই chapter খুব গুরুত্বপূর্ণ।

# 30.1 Memory Management কী?

Program চলার সময় বিভিন্ন data রাখার জন্য computer memory ব্যবহার করে।

যেমন:

```javascript
const name = "Ripon";
const age = 23;

const user = {
    name: "Ripon",
    age: 23
};
```

এই data program চলার সময় memory-তে রাখা হয়।

তারপর যখন data আর প্রয়োজন হয় না, JavaScript সেই memory reclaim করার ব্যবস্থা করে।

এই পুরো process:

```text
Memory Allocation
       ↓
Use Memory
       ↓
No Longer Needed
       ↓
Garbage Collection
       ↓
Memory Reclaimed
```

---

# 30.2 JavaScript কি নিজে Memory Manage করে?

হ্যাঁ।

C/C++-এর মতো language-এ developer-কে অনেক ক্ষেত্রে manually memory manage করতে হয়।

JavaScript-এ সাধারণত:

```text
Developer
   ↓
Create Object
   ↓
JavaScript Runtime
   ↓
Memory Management
   ↓
Garbage Collector
```

তাই JavaScript-কে **garbage-collected language** বলা হয়।

---

# 30.3 Memory Lifecycle

একটি সাধারণ memory lifecycle:

```text
1. Allocate
      ↓
2. Use
      ↓
3. No longer reachable
      ↓
4. Garbage Collector detects
      ↓
5. Memory reclaimed
```

উদাহরণ:

```javascript
let user = {
    name: "Ripon"
};
```

Object তৈরি হলো।

পরে:

```javascript
user = null;
```

যদি object-এর আর কোনো reference না থাকে, objectটি garbage collection-এর জন্য eligible হতে পারে।

# 30.4 Memory Allocation

যখন আমরা data তৈরি করি:

```javascript
const name = "Ripon";
```

অথবা:

```javascript
const numbers = [10, 20, 30];
```

অথবা:

```javascript

    name: "Ripon"

```

JavaScript runtime প্রয়োজন অনুযায়ী memory allocate করে।

Conceptually:

```text
name
 ↓
"Ripon"

numbers
 ↓
[10, 20, 30]

user
 ↓
{ name: "Ripon" }
```

# 30.5 Stack vs Heap

Chapter 29-এ আমরা Call Stack এবং Heap দেখেছিলাম।

Memory-এর basic mental model:

```text
Stack
----------------
Execution-related
Primitive values / references
Function frames
----------------

Heap
----------------
Objects
Arrays
Functions
Dynamic data
----------------
```

তবে একটি গুরুত্বপূর্ণ কথা:

> Stack বনাম Heap-এর exact implementation JavaScript specification দ্বারা এভাবে নির্ধারিত নয়। এটি বোঝার জন্য একটি useful conceptual model।

# 30.7 Objects এবং Reference

Object:

```javascript
const user = {
    name: "Ripon"
};
```

এখানে `user` variable object-এর সাথে একটি reference-এর মাধ্যমে সম্পর্কিত।

Conceptually:

```text
user
 │
 ▼
┌─────────────────┐
│ Object          │
│ name: "Ripon"   │
└─────────────────┘
```

---

# 30.8 Reference কী?

দেখো:

```javascript
const user1 = {
    name: "Ripon"
};

const user2 = user1;
```

এখন:

```text
user1 ─────┐
           ▼
       ┌──────────┐
       │ Object   │
       │ Ripon    │
       └──────────┘
           ▲
           │
user2 ─────┘
```

দুটো variable একই object-কে reference করছে।

তাই:

```javascript
user2.name = "Shariar";

console.log(user1.name);
```

Output:

```text
Shariar
```

কারণ `user1` এবং `user2` একই object-এর দিকে reference করছে।

---

# 30.9 Primitive Copy vs Reference

Primitive:

```javascript
let a = 10;
let b = a;

b = 20;

console.log(a);
```

Output:

```text
10
```

কারণ primitive value copy হয়েছে।

অন্যদিকে:

```javascript
const a = {
    value: 10
};

const b = a;

b.value = 20;

console.log(a.value);
```

Output:

```text
20
```

কারণ একই object reference করা হয়েছে।

# 30.10 Reachability — সবচেয়ে গুরুত্বপূর্ণ Concept 🔥

Garbage Collection বোঝার জন্য সবচেয়ে গুরুত্বপূর্ণ concept:

> **Reachability**

সহজভাবে:

> কোনো object যদি program-এর active references থেকে এখনও পৌঁছানো যায়, তাহলে সেটি reachable।

আর যদি আর কোনো active reference দিয়ে পৌঁছানো না যায়, তাহলে সেটি garbage collection-এর জন্য eligible হতে পারে।

---

# 30.11 Root কী?

Garbage Collector সাধারণত কিছু **roots** থেকে object reachability track করার concept ব্যবহার করে।

Examples:

* Global references
* বর্তমানে executing function-এর reachable references
* অন্যান্য runtime roots

Simplified:

```text
ROOT
 │
 ▼
Object A
 │
 ▼
Object B
```

যদি Root থেকে B পর্যন্ত পৌঁছানো যায়:

```text
B = Reachable
```

---

# 30.12 Reachable Example

```javascript
let user = {
    name: "Ripon"
};
```

Conceptually:

```text
Global
  │
  ▼
user
  │
  ▼
Object
```

Object reachable।

---

# 30.13 Unreachable Object

এখন:

```javascript
let user = {
    name: "Ripon"
};

user = null;
```

আগের object-এর দিকে আর `user` reference নেই।

Conceptually:

```text
Global
  │
  X

Object
```

Object unreachable হয়ে যেতে পারে।

তখন Garbage Collector পরে সেটার memory reclaim করতে পারে।

---

# 30.14 Garbage Collection কী?

Garbage Collector-এর কাজ:

> যেসব object আর reachable নয় এবং আর ব্যবহার করা সম্ভব নয়, সেগুলোর memory reclaim করা।

সহজভাবে:

```text
Object created
      ↓
Used
      ↓
No reference
      ↓
Unreachable
      ↓
Garbage Collector
      ↓
Memory reclaimed
```

---

# 30.15 Garbage Collection Manual নয়

তুমি সাধারণত এমন code লিখবে না:

```javascript
free(user);
```

JavaScript-এ সাধারণভাবে এইভাবে manually object free করতে হয় না।

বরং:

```javascript
user = null;
```

এর মাধ্যমে reference remove করতে পারো।

তারপর object unreachable হলে GC পরে memory reclaim করতে পারে।

---

# 30.16 `null` কি Object Delete করে?

এটা খুব important।

```javascript
let user = {
    name: "Ripon"
};

user = null;
```

`null` বসানোর সাথে সাথে object **অবশ্যই সঙ্গে সঙ্গে delete হয়ে যায়**—এমন নয়।

বরং:

```text
user reference removed
       ↓
Object may become unreachable
       ↓
GC may reclaim later
```

Garbage collection-এর timing runtime control করে।

---

# 30.17 Garbage Collection সঙ্গে সঙ্গে হয় না

```javascript
let data = {
    huge: "some data"
};

data = null;
```

এখন object unreachable হতে পারে।

কিন্তু:

```text
data = null
```

হওয়ার সাথে সাথেই GC necessarily run করবে—এটা ধরে নেওয়া ঠিক নয়।

Garbage Collector কখন memory reclaim করবে সেটা runtime-এর implementation এবং heuristics-এর ওপর নির্ভর করে।

# 30.18 Mark-and-Sweep

Garbage Collection বোঝার জন্য classic concept:

> **Mark-and-Sweep**

Simplified process:

```text
Step 1
Start from roots

Step 2
Mark reachable objects

Step 3
Find unmarked objects

Step 4
Reclaim their memory
```

---

# 30.19 Mark-and-Sweep Example

ধরো:

```text
Root
 │
 ▼
 A
 │
 ▼
 B

C
```

এখানে:

```text
Root → A → B
```

তাই:

```text
A = reachable
B = reachable
C = unreachable
```

Garbage Collector:

```text
Mark:
A ✓
B ✓
C ✗

Sweep:
C removed/reclaimed
```

# 30.20 Circular Reference

আগে পুরনো কিছু garbage collection model-এ circular reference নিয়ে সমস্যা ছিল।

কিন্তু modern JavaScript garbage collectors শুধু reference count-এর ওপর নির্ভর করে না; reachability-based tracing techniques ব্যবহার করে।

উদাহরণ:

```javascript
let a = {};

let b = {};

a.other = b;
b.other = a;
```

এখন:

```text
a → b
↑   ↓
└───┘
```

এটি circular reference।

পরে:

```javascript
a = null;
b = null;
```

যদি আর কোনো root reference না থাকে:

```text
Root
 X
```

পুরো cycle unreachable হতে পারে এবং garbage collection-এর জন্য eligible হতে পারে।

---

# 30.21 Reference Counting কেন যথেষ্ট নয়?

যদি শুধু reference count ব্যবহার করা হতো:

```text
A → B
B → A
```

তাহলে:

```text
A count = 1
B count = 1
```

দেখে মনে হতে পারে তারা এখনও alive।

কিন্তু Root থেকে কেউ তাদের access করতে পারছে না।

তাই modern GC reachability-based tracing অনেক বেশি useful।

# 30.22 Memory Leak কী?

**Memory Leak** হলো এমন situation যেখানে program-এর আর প্রয়োজন নেই এমন memory references-এর কারণে memory unnecessarily retained থাকে।

সহজভাবে:

```text
Memory ব্যবহার হচ্ছে
       ↓
Data আর দরকার নেই
       ↓
কিন্তু reference রয়ে গেছে
       ↓
GC reclaim করতে পারছে না
       ↓
Memory usage বাড়ছে
```

---

# 30.23 Memory Leak Example — Global Variable

```javascript
window.myData = [];

function addData(data) {
    window.myData.push(data);
}
```

যদি application continuously বড় data যোগ করে:

```text
myData
 ↓
Huge Array
 ↓
More Data
 ↓
More Data
```

এবং application-এর আর প্রয়োজন না থাকলেও global reference ধরে রাখে, memory বাড়তে পারে।

---

# 30.24 Event Listener Memory Leak

একটি common frontend problem:

```javascript
const button = document.querySelector("#button");

function handleClick() {
    console.log("Clicked");
}

button.addEventListener("click", handleClick);
```

যদি dynamically created component পরে remove করা হয় কিন্তু listener lifecycle ঠিকভাবে manage না করা হয়, কিছু situation-এ unnecessary references retain হতে পারে।

বিশেষ করে SPA/framework applications-এ lifecycle management গুরুত্বপূর্ণ।

---

# 30.25 Event Listener Cleanup

যদি listener আর দরকার না হয়:

```javascript
button.removeEventListener("click", handleClick);
```

Important:

```javascript
button.addEventListener("click", handleClick);
```

এর পরে remove করতে হলে একই function reference ব্যবহার করা ভালো:

```javascript
button.removeEventListener("click", handleClick);
```

---

# 30.26 Anonymous Function-এর Common Problem

```javascript
button.addEventListener("click", () => {
    console.log("Clicked");
});
```

পরে:

```javascript
button.removeEventListener("click", () => {
    console.log("Clicked");
});
```

এটা listener remove করবে না।

কারণ দুইটা function আলাদা।

```text
First function ≠ Second function
```

Better:

```javascript
function handleClick() {
    console.log("Clicked");
}

button.addEventListener("click", handleClick);

button.removeEventListener("click", handleClick);
```

# 30.27 Detached DOM Node

Frontend-এ একটি গুরুত্বপূর্ণ memory issue:

> Detached DOM node

ধরো:

```javascript
const div = document.createElement("div");

const data = {
    name: "Ripon"
};

div.data = data;
```

তারপর DOM থেকে node remove করলে:

```javascript
div.remove();
```

কিন্তু যদি অন্য কোথাও `div`-এর reference থেকে যায়:

```javascript
someGlobalReference = div;
```

তাহলে node এবং তার associated references memory-তে retained থাকতে পারে।

# 30.28 DOM Memory Leak-এর Simple Mental Model

```text
JavaScript Reference
       ↓
DOM Node
       ↓
More Data
```

DOM থেকে remove করলেই সব memory সঙ্গে সঙ্গে free হবে না।

যদি JavaScript থেকে এখনও reference থাকে:

```text
JS Reference
     ↓
DOM Node
```

তাহলে সেটা reachable থাকতে পারে।

# 30.29 Closure এবং Memory

Chapter 26-এ closure দেখেছিলাম।

Closure outer variables retain করতে পারে।

```javascript
function createCounter() {
    let count = 0;

    return function () {
        count++;
        return count;
    };
}

const counter = createCounter();
```

এখন `counter` function-এর মাধ্যমে:

```text
count
```

accessible।

Conceptually:

```text
counter
  ↓
closure
  ↓
count
```

তাই closure-এর lifetime বুঝতে memory concepts গুরুত্বপূর্ণ।

---

# 30.30 Closure Memory Leak হতে পারে?

Closure নিজে memory leak নয়।

কিন্তু closure যদি accidentally বড় object/reference ধরে রাখে এবং সেটা দীর্ঘসময় reachable থাকে, তাহলে unnecessary memory retention হতে পারে।

উদাহরণ:

```javascript
function createHandler() {
    const hugeData = new Array(1000000).fill("data");

    return function () {
        console.log(hugeData.length);
    };
}

const handler = createHandler();
```

`handler` যতক্ষণ `hugeData`-কে closure-এর মাধ্যমে retain করে, ততক্ষণ সেই data reachable থাকতে পারে।

---

# 30.31 Function Scope এবং Memory

```javascript
function test() {
    const data = {
        name: "Ripon"
    };

    console.log(data);
}

test();
```

`test()` execution শেষ হলে সাধারণভাবে `data` আর reachable না থাকলে তার associated memory GC-এর জন্য eligible হতে পারে।

---

# 30.32 But Closure Changes the Lifetime

```javascript
function test() {
    const data = {
        name: "Ripon"
    };

    return function () {
        return data;
    };
}

const getData = test();
```

এখন:

```text
getData
   ↓
closure
   ↓
data
```

তাই `test()` শেষ হলেও `data` retain হতে পারে।

---

# 30.33 `WeakMap` কেন?

Chapter 12-এ আমরা `WeakMap` দেখেছি।

Memory management-এর দিক থেকে `WeakMap` গুরুত্বপূর্ণ।

```javascript
const weakMap = new WeakMap();

let user = {
    name: "Ripon"
};

weakMap.set(user, "Private Data");
```

যদি:

```javascript
user = null;
```

এবং object-এর আর কোনো strong reference না থাকে, `WeakMap` সেই object-কে এমনভাবে retain করে না যাতে garbage collection বাধ্যতামূলকভাবে বন্ধ হয়ে যায়।

---

# 30.34 WeakMap-এর Mental Model

Normal Map:

```text
Map
 ↓
Object
 ↓
Strong reference
```

WeakMap:

```text
WeakMap
   ↓
Object
   ↓
Weak association
```

তাই object অন্য কোথাও unreachable হলে WeakMap-এর association garbage collection-এর সাথে disappear হতে পারে।

---

# 30.35 WeakSet

একই ধারণা `WeakSet`-এর ক্ষেত্রেও।

```javascript
const weakSet = new WeakSet();

let user = {
    name: "Ripon"
};

weakSet.add(user);

user = null;
```

যদি আর কোনো strong reference না থাকে, object garbage collection-এর জন্য eligible হতে পারে।

---

# 30.36 WeakMap কোথায় ব্যবহার করা হয়?

একটি practical example:

```javascript
const metadata = new WeakMap();

function setMetadata(element, data) {
    metadata.set(element, data);
}
```

DOM element:

```javascript
const button = document.querySelector("button");

setMetadata(button, {
    clicked: true
});
```

যদি button পরে DOM এবং application-এর অন্য strong references থেকে চলে যায়, WeakMap-এর association object lifetime-এর সাথে automatically disappear করতে পারে।

# 30.37 Cache এবং Memory

Caching performance বাড়ায়:

```javascript
const cache = new Map();

cache.set("user:1", {
    name: "Ripon"
});
```

কিন্তু unlimited cache:

```text
Cache
 ↓
Data
 ↓
More Data
 ↓
More Data
 ↓
Huge Memory
```

হতে পারে।

তাই cache design করতে হয়:

* Maximum size
* Expiration
* LRU strategy
* Cleanup
* Appropriate data structure

# 30.38 Infinite Array — Memory Problem

```javascript
const data = [];

setInterval(() => {
    data.push(new Array(10000).fill("data"));
}, 100);
```

এখানে array ক্রমাগত বড় হচ্ছে।

```text
data
 ↓
10000
 ↓
20000
 ↓
30000
 ↓
...
```

Memory usage continuously বাড়তে পারে।

# 30.39 Memory Leak vs High Memory Usage

দুটো এক নয়।

### High Memory Usage

Program legitimately বড় data ব্যবহার করছে।

### Memory Leak

Program-এর প্রয়োজন না থাকা data/reference unnecessarily retained হচ্ছে।

Example:

```text
High memory:
Large image processing
```

vs

```text
Leak:
Old objects never released
```

# 30.40 Garbage Collection-এর Cost

Garbage Collection automatic হলেও completely free নয়।

GC-এর জন্য:

```text
CPU
+
Memory
+
Time
```

ব্যবহার হতে পারে।

যদি application continuously huge temporary objects তৈরি করে:

```javascript
function process() {
    const huge = new Array(1000000).fill(0);
}
```

অনেক repeated allocation হলে GC pressure বাড়তে পারে।

# 30.41 Allocation Pressure

ধরো:

```javascript

    const obj = {

```

অনেক temporary object তৈরি হচ্ছে।

এগুলো পরে unreachable হলে GC reclaim করতে পারে।

কিন্তু excessive allocation performance-এর ওপর চাপ তৈরি করতে পারে।

# 30.42 Object Creation Optimization

প্রয়োজনের বাইরে বারবার object তৈরি করা avoid করা যায়।

Bad pattern:

```javascript
function calculate(user) {
    return {
        name: user.name,
        age: user.age
```

যদি millions of unnecessary temporary objects তৈরি হয়, performance impact হতে পারে।

তবে premature optimization করা উচিত নয়।

প্রথমে:

> Correctness → Measure → Optimize

# 30.48 `WeakRef`

JavaScript-এ advanced feature:

```javascript
WeakRef
```

এটি object-এর weak reference তৈরি করতে পারে।

Example:

```javascript
let user = {
    name: "Ripon"
};

const weakRef = new WeakRef(user);
```

পরে:

```javascript
const value = weakRef.deref();
```

object এখনও available থাকলে object পাওয়া যেতে পারে।

কিন্তু object garbage collected হয়ে গেলে:

```javascript
weakRef.deref();
```

`undefined` দিতে পারে।

---

# 30.49 WeakRef কেন সাধারণভাবে Avoid করা হয়?

`WeakRef` advanced use case-এর জন্য।

কারণ garbage collection timing deterministic নয়।

তাই normal application logic এভাবে design করা উচিত নয়:

```text
"GC কখন object remove করবে?"
```

এর ওপর নির্ভর করে।

# 30.50 `FinalizationRegistry`

আরেকটি advanced feature:

```javascript
FinalizationRegistry
```

এটি object garbage-collected হওয়ার পরে cleanup-related notification-এর জন্য ব্যবহার করা যেতে পারে।

কিন্তু এটাও:

> deterministic cleanup mechanism নয়।

Critical resource cleanup-এর জন্য এর ওপর নির্ভর করা উচিত নয়।

# 30.51 Resource Cleanup বনাম Garbage Collection

খুব গুরুত্বপূর্ণ distinction।

# 30.56 React-এর সাথে Memory Management

```text
      ↓
```

# 30.57 Memory Leak Example — React Style

Problematic pattern:

```javascript
useEffect(() => {
    const id = setInterval(() => {
        fetchData();
    }, 1000);
}, []);
```

যদি effect lifecycle-এর সাথে timer cleanup না করা হয়, component lifecycle অনুযায়ী unnecessary interval running/retention হতে পারে।

Better:

```javascript
useEffect(() => {
    const id = setInterval(() => {
        fetchData();
    }, 1000);

    return () => {
        clearInterval(id);
    };
}, []);
```

# 30.61 Closure Question

```javascript

    const secret = "Hello";

    return function () {
        console.log(secret);
    };

```

`create()` execution শেষ হলেও `secret` কেন থাকতে পারে?

কারণ:

```text
fn
 ↓
Closure
 ↓
secret
```

`fn` যতক্ষণ reachable এবং closure `secret` ব্যবহার করতে পারে, `secret` retained হতে পারে।
